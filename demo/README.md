# M1 / Contact DRC Demo

A minimal side-by-side demo of **Metal 1** and **Contact** design rules using **KLayout DRC** and **Calibre DRC**. Both decks check the same five rules on the same test layout.

## What this demo covers

| Rule | Value | KLayout category | Calibre rule |
|------|-------|------------------|--------------|
| M1 minimum width | 0.14 µm | `M1.min_width` | `M1_MIN_WIDTH` |
| M1 minimum spacing | 0.14 µm | `M1.min_space` | `M1_MIN_SPACE` |
| Contact minimum width | 0.16 µm | `CT.min_width` | `CT_MIN_WIDTH` |
| Contact minimum spacing | 0.18 µm | `CT.min_space` | `CT_MIN_SPACE` |
| M1 enclosure of contact | 0.055 µm | `M1.over_CT.enclosure` | `M1_OVER_CT_ENCLOSURE` |

**Layers:** M1 = GDS **31/0**, Contact = GDS **30/0**, labels = **90/0**

**Expected result:** all intentionally bad rows fail. KLayout reports **8** markers (enclosure yields 4 edge-pairs); Calibre reports **5** rule results (enclosure is one polygon result).

## Quick start

### 1. Generate the test layout

Requires [KLayout](https://www.klayout.de/) on `PATH` (see `../scripts/install-klayout.sh`).

```bash
cd demo
./run_demo.sh --gen-only
# or
klayout -b -rd output=m1_contact_demo.gds -r generate_layout.rb
```

### 2. Run KLayout DRC

```bash
./run_demo.sh              # generate GDS + run DRC
./run_demo.sh --drc-only   # DRC only

# View violations in the GUI (layout + markers)
./view_klayout_drc.sh
# or manually:
klayout m1_contact_demo.gds -m m1_contact.lyrdb
```

Batch mode:

```bash
klayout -b \
  -rd input=m1_contact_demo.gds \
  -rd report=m1_contact.lyrdb \
  -r m1_contact.drc
```

### 3. Run Calibre DRC

Requires a licensed Calibre install. This demo’s `calibre.env` already points at the site install + license file.

**UI-friendly (recommended)** — layout path comes from calibredrv, not from env vars:

```bash
./view_calibre_drc.sh                 # run DRC via DESIGNrev Tcl, then open RVE
./view_calibre_drc.sh --no-gui        # headless (no RVE window)
```

Inside an already-open DESIGNrev session:

```tcl
source /path/to/demo/run_drc_in_calibredrv.tcl
run_m1_contact_drc
```

**Batch** (still no `$GDS`/`$RDB` in the rule file — the shell writes a tiny `INCLUDE` run deck):

```bash
./run_calibre_drc.sh              # generate GDS + run DRC
./run_calibre_drc.sh --drc-only   # DRC only
./run_calibre_drc.sh --view       # run DRC + open RVE
```

`m1_contact.calibre.svrf` contains **rules only**. Layout / results paths are filled in by calibredrv or by the batch wrapper.

## Test structures in the GDS

Each row is labeled on layer 90/0. **GOOD** rows should pass; **BAD** rows should fail exactly one rule (enclosure row produces 4 edge markers).

| Row label | Checks |
|-----------|--------|
| GOOD M1 width 0.20 µm | M1 width |
| BAD M1 width 0.10 µm | → `M1.min_width` |
| GOOD M1 space 0.20 µm | M1 spacing |
| BAD M1 space 0.08 µm | → `M1.min_space` |
| GOOD CT 0.20 + M1 enc 0.08 µm | CT width + M1 enclosure |
| BAD M1 enc 0.03 µm | → `M1.over_CT.enclosure` |
| GOOD CT space 0.25 µm | CT spacing (contacts on M1 slab) |
| BAD CT space 0.12 µm | → `CT.min_space` |
| BAD CT width 0.12 µm | → `CT.min_width` |

## KLayout vs Calibre — coding comparison

Both decks express the same physical checks. The main differences are **language** (Ruby DSL vs SVRF), **layer declaration**, and **how results are written**.

### Setup: layout input and reporting

**KLayout** (`m1_contact.drc`) — Ruby script; layout comes from the active window or `source()`; report is an object you write to:

```ruby
source($input)                                        # load GDS
report("M1 / Contact DRC demo", "m1_contact.lyrdb", "M1_CT_DRC_DEMO")
def_output.rdb.original_file = $input                 # link RDB → GDS for GUI

metal1  = input(31, 0)
contact = input(30, 0)
```

**Calibre** (`m1_contact.calibre.svrf`) — rules only; layout/RDB paths come from calibredrv or a tiny generated run deck:

```svrf
LAYER M1 31 0
LAYER CT 30 0
# LAYOUT PATH / RDB are NOT in this file —
# calibredrv Tcl reads [$L file] / [$L topcell], or the batch
# wrapper writes a temp run deck that INCLUDEs these rules.
```

| Aspect | KLayout | Calibre |
|--------|---------|---------|
| Language | Ruby DSL (`.drc`) | SVRF (`.svrf`) |
| Layer read | `input(31, 0)` | `LAYER M1 31 0` |
| Units | `.um` suffix (`0.14.um`) | Microns in rule text (`0.14`) |
| Output | `.output(category, description)` | `DRC RESULTS DATABASE` + rule blocks |
| GUI viewer | KLayout (`-m lyrdb`) | Calibre RVE (`calibredrv -rve`) |

### Rule-by-rule side-by-side

#### Minimum width (same polygon, internal dimension)

Checks that no part of a shape is narrower than the limit.

| | Code |
|---|------|
| **KLayout** | `metal1.width(0.14.um).output("M1.min_width", "...")` |
| **Calibre** | `INT M1 < 0.14 ABUT < 90 SINGULAR` inside `M1_MIN_WIDTH { ... }` |

KLayout uses a method on the layer object. Calibre uses **INT** (internal edge separation) on a named rule block.

#### Minimum spacing (between shapes on the same layer)

| | Code |
|---|------|
| **KLayout** | `metal1.space(0.14.um).output("M1.min_space", "...")` |
| **Calibre** | `EXT M1 M1 < 0.14 ABUT < 90 SINGULAR` inside `M1_MIN_SPACE { ... }` |

KLayout: one `space` call. Calibre: **EXT** (external separation) between two references to the same layer.

#### Enclosure (M1 must surround contact)

Primary layer (M1) must extend at least 0.055 µm beyond the secondary layer (CT) on all sides.

| | Code |
|---|------|
| **KLayout** | `metal1.enclosing(contact, 0.055.um).output("M1.over_CT.enclosure", "...")` |
| **Calibre** | `ENC M1 CT < 0.055 OPPOSITE` inside `M1_OVER_CT_ENCLOSURE { ... }` |

Argument order matches: **enclosing layer first, enclosed layer second**.

#### Contact rules (same pattern as M1)

| Check | KLayout | Calibre |
|-------|---------|---------|
| CT width | `contact.width(0.16.um)` | `INT CT < 0.16 ...` |
| CT space | `contact.space(0.18.um)` | `EXT CT CT < 0.18 ...` |

### Full decks at a glance

**KLayout** — imperative, chain `.output()` per check:

```ruby
M1_MIN_WIDTH = 0.14
metal1 = input(31, 0)
contact = input(30, 0)

metal1.width(M1_MIN_WIDTH.um).output("M1.min_width", "Metal1 width < #{M1_MIN_WIDTH} µm")
metal1.space(M1_MIN_SPACE.um).output("M1.min_space", "...")
contact.width(CT_MIN_WIDTH.um).output("CT.min_width", "...")
contact.space(CT_MIN_SPACE.um).output("CT.min_space", "...")
metal1.enclosing(contact, M1_OVER_CT_ENC.um).output("M1.over_CT.enclosure", "...")
```

**Calibre** — rule blocks with geometry operations:

```svrf
M1_MIN_WIDTH {
  @ Metal1 width < 0.14 um
  INT M1 < 0.14 ABUT < 90 SINGULAR
}

M1_MIN_SPACE {
  EXT M1 M1 < 0.14 ABUT < 90 SINGULAR
}

M1_OVER_CT_ENCLOSURE {
  ENC M1 CT < 0.055 OPPOSITE
}
```

### Concept mapping

| Concept | KLayout DRC | Calibre SVRF |
|---------|-------------|--------------|
| Min width / notch | `layer.width(d)` | `INT layer < d` |
| Min space (same layer) | `layer.space(d)` | `EXT layer layer < d` |
| Enclosure | `a.enclosing(b, d)` | `ENC a b < d` |
| Rule parameters | Ruby variables | Literals in rule (or `#DEFINE` / `-E`) |
| Categories | First `.output()` string | Rule block name (`M1_MIN_WIDTH`) |
| Run command | `klayout -b -r script.drc` | `calibre -drc -hier rules.svrf` |

### Practical differences

1. **KLayout** rules are short Ruby scripts — easy to prototype in the GUI (**Tools → DRC**), reuse logic with variables and loops, and inspect results in the same app.
2. **Calibre** rules are industry-standard SVRF — verbose but portable across fabs; hierarchical `-hier -turbo` runs are typical for production.
3. **KLayout** `.lyrdb` links to the source GDS via `original-file` (set in this demo) and opens with `klayout layout.gds -m report.lyrdb`.
4. **Calibre** ASCII `.rdb` opens in **Calibre RVE** (`calibredrv layout.gds -rve report.rdb` or `./run_calibre_drc.sh --view`).
